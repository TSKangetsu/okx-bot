## 四、 OKX API 与 `okx_ctl.py` 工程演进及排障经验汇总 (Technical Troubleshooting)

1. **OKX API `sCode: 50123` 权限报错修复**：
   - **现象**：首次调用 `/api/v5/trade/order` 下单返回 `50123` 错误，而查询余额接口正常。
   - **原因与解决**：OKX API Key 刚开启“交易（Trade）”权限或绑定 IP 后存在短暂同步延迟，需通过小额实盘指令验证权限生效后再挂载全套策略。
2. **跨币种全仓账户（`auto_transfers_ccy`）下的保证金模式冲突**：
   - **现象**：账户开启跨币种自动借币/全仓模式时，使用 `tdMode="isolated"`（逐仓）易出现保证金划转受限或单笔占用计算偏差。
   - **解决**：统一规范为 **`tdMode="cross"`（100x 全仓模式）+ 服务端 `conditional` 硬止损单**，既利用账户整体保证金缓冲防极端插针，又通过服务端止损单将实际最大亏损物理锁死在授权红线以内。
3. **`place_short` 保证金与最大亏损解耦校准**：
   - **问题**：早期脚本直接用 `max_loss / sl_dist` 反推张数，导致当止损设宽时，实际动用的保证金远小于用户要求的额度。
   - **修复**：在 [`okx_ctl.py`](file:///home/user/okx-bot/okx_ctl.py) 中重构 `place_short`，严格按照 `target_contracts = (margin_usdt * 100.0) / (ref_px * 0.1)` 足额对齐 100x 保证金，同时校验 `actual_max_loss <= max_loss_usdt`（默认 `2/3 * margin`）。
4. **`aiohttp.ClientTimeout` 导致长周期监控模式提前断连修复**：
   - **问题**：切换至 `900s` 或 `7200s` 低频盯盘模式时，WebSocket 进程在运行约 30 秒后无预警退出。
   - **根因与修复**：`aiohttp.ClientSession()` 默认存在读取超时限制；在 `cmd_watch_async` 中显式配置 `timeout=aiohttp.ClientTimeout(total=None, sock_connect=15, sock_read=None)` 并设 `heartbeat=20`，彻底解决长效值守断连问题。
5. **双向破位触发器与巨鲸逐笔流（`--support` / `--whale-sz`）扩展**：
   - **问题**：早期 `watch` 仅监控上方阻力与远端固定止盈，导致下拉瀑布破位初期及盘口巨鲸市价大单交锋时缺乏毫秒级感知，且在高频肉搏期 `--whale-sz 300` 唤醒过于密集。
   - **升级**：在 [`okx_ctl.py`](file:///home/user/okx-bot/okx_ctl.py) 中新增 `--support <px>`（`PROFIT_STEP_BREAKDOWN_ALERT` 阶梯下破告警）、`CLIMAX_REBOUND_ALERT`（深跌触底快速反抽告警）以及可调参的 `--whale-sz <contracts>`（默认 `1500 张`，支持按需在 `300 / 1500 / 2000 / 5000 张` 间灵活切换），并扩展 `close --sz <contracts>` 支持任意精确张数平仓测试。
6. **`amend-algo` CLI 参数名规范提醒**：
   - 修改止损/止盈时，[`okx_ctl.py`](file:///home/user/okx-bot/okx_ctl.py) 的标准参数名为 `--sl <px>`、`--tp <px>`、`--sz <contracts>`（切勿误传 `--sl-px` 导致 `unrecognized arguments` 报错延误战机）。
