# ETH-USDT-SWAP 极低功耗三层狙击架构（测试版 Skill）

> **设计定位**：本文件为独立存放的测试版技能规范（[`eth-sniper-test/SKILL.md`](file:///home/user/okx-bot/eth-sniper-test/SKILL.md)），不修改原有正式版 [`eth-sniper/SKILL.md`](file:///home/user/okx-bot/eth-sniper/SKILL.md)。重点验证 **“本地状态差值持久化 + 一次性 `flash` Subagent 用完即毁 + 纯事件驱动零轮询”** 的极限省 Token 实战流程。

## 1. 核心降本原理：为什么传统盯盘消耗海量 Token？

1. **主对话上下文复利膨胀（最大出血点）**：
   * 每次在主对话直接运行 `snapshot`、`orderbook` 或 `search_web`，返回的 200~300 行原始 JSON 数据会永久写入主对话历史。在后续每一轮交互中，这些过期 JSON 都会被重复计费。
2. **无效的固定时间轮询 (`Cron`)**：
   * 在缩量横盘期（波动 `< 2.5 USDT`），固定 `60s / 15m` 定时唤醒大模型属于纯浪费。
3. **Subagent 长期复用导致子上下文膨胀**：
   * 如果同一个 Subagent 被连续唤醒 5~10 次而不销毁，它自身的上下文也会堆积上万 Token 的历史垃圾。

## 2. 三层极低功耗协同架构 (3-Tier Zero-Waste Architecture)

```
[第 1 层：Python 本地进程 (okx_ctl.py)]  --> 0 Token 消耗
  ├─ WebSocket 毫秒级盯盘 (价格越界 / 巨鲸市价单 / 阶梯破位)
  ├─ 本地状态差值缓存 (/tmp/okx_last_state.json 记录上一次 OI, LSR, 巨鲸墙)
  └─ 仅在触发硬性阈值时退出进程，唤醒上层
          │
          ▼ (事件触发)
[第 2 层：一次性侦察兵 Subagent (Model: "flash")] --> 极低 Token (0 历史包袱 + 轻量模型)
  ├─ 独立沙箱运行 orderbook / snapshot / 强平统计 / search_web
  ├─ 读取本地 /tmp/okx_last_state.json 自动计算 ΔOI、ΔLSR、挂单墙位移
  ├─ 过滤 95% 原始 JSON 噪音，向主脑输出 <= 150 字结构化情报
  └─ 【用完即焚】：汇报完毕立即终止/弃用，绝不跨轮次堆积上下文
          │
          ▼ (150字高浓缩情报)
[第 3 层：主控 Agent (Pro 主脑)] --> 主上下文永远干净极简
  ├─ 仅接收用户指令与 Flash 侦察兵的百字结论
  └─ 拍板核心实盘动作：建仓 (short)、移损 (amend-algo)、平仓 (close)
```

## 3. Subagent 生命周期管理铁律（用完即毁 vs 波段换防）

### 3.1 盘口/强平/新闻侦察 Subagent：**100% 用完即焚 (One-Shot & Discard)**
* **定义配置**：
  * 使用 `define_subagent` 创建名为 `okx-flash-scout` 的子智能体（开启 `enable_write_tools=True` 以便执行 CLI 命令）。
  * 调用 `invoke_subagent` 时，强制指定 **`Model="flash"`**（或 `"flash_lite"`）。
* **单次生命周期**：
  1. 主 Agent 发起 `invoke_subagent(TypeName="okx-flash-scout", Model="flash", ...)`；
  2. `okx-flash-scout` 在独立上下文内执行盘口/强平/状态对比命令；
  3. `okx-flash-scout` 将结果浓缩为 **8 行以内的 Markdown 摘要** 返回给主 Agent；
  4. **严禁二次唤醒**：下一次需要查盘口时，**绝不使用 `send_message` 唤醒旧实例**（避免为旧实例肚子里的 300 行历史 JSON 买单），而是直接 `invoke_subagent` 启动一个全新的 `flash` 实例，必要时调用 `manage_subagents(Action="kill")` 清理旧实例。

### 3.2 历史连续性如何保障？（本地磁盘记忆替代模型 Token 记忆）
* 为了让“每次全新开启的 `flash` Subagent”依然知道主力挂单是在下压还是撤退，**将记忆存储在本地文件 `/tmp/okx_last_state.json` 中，而不是存储在模型的上下文里**：
  * 每次运行盘口审计时，Python 自动读取 `/tmp/okx_last_state.json`（包含上一次的 `timestamp`、`price`、`oi_eth`、`long_short_ratio`、`top_ask_wall`、`top_bid_wall`）；
  * Python 直接在终端输出计算好的差值（例如：`ΔOI: +12,400 ETH | ΔLSR: +0.07 | 2382卖墙: +5,200张 (主力下压)`），随后覆盖更新该 JSON 文件；
  * 全新的 `flash` Subagent 只需看一眼这行差值输出，就能获得完整的历史演变视野，实现 **“零历史 Token 消耗 + 完整时序记忆”**。

### 3.3 后台值班哨兵 Subagent（若开启全托管盯盘模式）
* 若将 `watch` 循环也托管给后台 `flash` Subagent：
  * **最多复用 3 次唤醒**：同一个哨兵实例在过滤了 3 次假突破/杂波后，必须主动向主脑请求 **“换防销毁 (`kill` & respawn)”**，由主脑传入一句话最新基准后开启新实例。
  * **阶段切换必重开**：一旦发生开仓、加仓、止损下移或平仓，旧哨兵立即销毁。

## 4. 混合触发调度机制：实时事件驱动 + 黄金时间节点体检 (Event + Time-Node Protocol)

为避免“机械每 15 分钟轮询烧光 Token”，同时克服“100% 纯事件触发无法感知横盘期 LSR/OI 暗中暴增与主力悄然移墙”的盲区，全面采用 **“WebSocket 毫秒级事件触发 + 黄金变盘时间节点精准体检”** 双轨制：

### 4.1 实时事件触发器（第 1 层 `okx_ctl.py watch` 全天候静默值守，0 Token）
仅在以下硬性事件发生时秒级退出 `watch` 并唤醒上层：
* **事件 A（左侧狙击唤醒 `RESISTANCE_BREAKOUT_ALERT`）**：价格刺入预设阻力伏击区（`--resistance <px>`）；
* **事件 B（双轨右侧破位/阶梯锁利唤醒 `PROFIT_STEP_BREAKDOWN_ALERT`）**：价格跌破预设支撑（`--support <px>`）**或**跌破自动 5U 整数阶梯（`auto_step_px`，两者并存不互斥，彻底杜绝因 `--support` 设太远导致主跌浪漏报）；
* **事件 C（急跌瀑布速率唤醒 `WATERFALL_DROP_ALERT`）**：无论静态支撑设在何处，只要价格从本周期高点急速下杀 `>= 5.0 USDT`，强制秒级唤醒追空或锁利；
* **事件 D（巨鲸单笔 + 20s 冰山拆单浪涌唤醒）**：
  * `WHALE_TRADE_ALERT`：单笔成交超越阈值（代码底层硬锁上限 `<= 2500 张`，日常设 `1500 ~ 2000 张`，严禁设 `5000` 致盲雷达）；
  * `SELL_VOLUME_SURGE_ALERT` / `BUY_VOLUME_SURGE_ALERT`：20 秒内累计主动砸盘或扫货 `>= 4,500 张（450 ETH）` 且单边占比 `>= 72%`、伴随价格位移 `>= 2.0 USDT`，精准捕获主力 TWAP 冰山拆单；
* **事件 E（持仓专属风控唤醒）**：`CLIMAX_REBOUND_ALERT`（触底反抽 `>= 3.8U` 止盈评估）与 `STOP_LOSS_APPROACH_ALERT`（距云端硬止损 `<= 1.5U`）**仅在实盘有持仓时激活**，空仓期自动静默以杜绝幽灵误报。
* **右侧破位强制审计铁律**：当空仓期由 `PROFIT_STEP_BREAKDOWN_ALERT`、`WATERFALL_DROP_ALERT` 或 `SELL_VOLUME_SURGE_ALERT` 唤醒时，**严禁不看盘口直接复读“空仓观望”**，必须立即运行 `scout_brief.py`（或派 `okx-flash-scout`）核验卖墙是否主动下压，确认破位立即追入底仓！

### 4.2 黄金变盘时间节点体检（第 2 层一次性 `flash` Subagent 定时点检）
彻底废除垃圾时间的机械轮询，区分 **“空仓狩猎期”** 与 **“持仓作战期”** 精准投放算力：

#### 模式一：空仓狩猎期（全天仅 6~8 个主力换防大节点，省流 92%）

#### 模式二：持仓作战期（`30m / 1H` 收线节点体检 + 实时移损事件触发）

* **瀑布加速阶段**：无需等待时间节点，由 `watch --support <阶梯位> --whale-sz 1500` 秒级触发唤醒，主脑立即执行棘轮下移止损 (`amend-algo`)。

## 6. 配套本地极简状态差值脚本规范 (`scout_brief.py` / `okx_ctl.py brief`)

为配合一次性 `flash` Subagent，本地执行脚本应在单次命令中完成以下聚合（避免 Subagent 多次调用工具）：
1. 拉取 `snapshot` 核心字段（剔除冗长的历史 K 线数组，仅保留最新 1 根指标与支撑阻力）；
2. 拉取 `orderbook` 400 档深度，按 `1U` 与 `5U` 自动聚类，提取 Top 3 巨鲸买卖墙；
3. 拉取 `/api/v5/public/liquidation-orders` 最近 100 笔强平，汇总多空爆仓张数与最大爆仓价格带；
4. 自动读写 `/tmp/okx_last_state.json`，计算并打印与上一次审计相比的 `ΔPrice`、`ΔOI`、`ΔLSR` 以及卖墙重心位移方向。
